Trang giả lập website khách

Trang này mô phỏng website của khách hàng có nhúng widget livechat Cluvix. Điền form bên dưới rồi bấm "Nạp widget" — script được chèn ĐỘNG (không cần sửa file này bằng tay).

Cách test tay

  1. Bảo đảm backend air chạy ở :8081 và đã build widget vào public/ (cd frontend/widget && npm run build:widget). Backend serve /widget.js, /widget.html, /api/* cùng origin.
  2. Tạo 1 site livechat (config omni-channel) và thêm origin của TRANG NÀY vào allowed_origins — ví dụ http://localhost:5500 (origin bạn serve file này). BE chỉ cho http với localhost/127.0.0.1.
  3. Serve thư mục dev/ qua static server ở đúng origin đã whitelist: npm run dev (từ frontend/widget/) → phục vụ ở http://localhost:5500. MỞ bằng origin đó, KHÔNG mở bằng file:// (Origin null sẽ bị 403).
  4. Điền Site key + Backend origin ở panel dưới (site_key nhận khi tạo site; backend origin = origin backend, vd http://localhost:8081) → bấm "Lưu + Nạp widget". Giá trị được lưu vào localStorage của trang này nên lần sau mở lại không cần điền lại.
  5. Bấm bong bóng → điền pre-chat (nếu bật) → chat. Mở inbox omnichat (staff) trả lời → tin hiện realtime ở widget; staff gõ → widget hiện “đang trả lời…”. Đóng widget, staff gửi tin → badge unread trên bong bóng.

Panel điều khiển demo

Chưa nạp widget.

"cluvixChat.setUser(vector test)" dùng ĐÚNG vector HMAC ở README (secret dev-only, identifier = "user-42") — chỉ hoạt động nếu site của bạn đang bật identity với secret đó. Xem README.vi.md.

Snippet nhúng

<script
  src="BACKEND_ORIGIN/widget.js"
  data-site-key="SITE_KEY_HERE"
  data-host="BACKEND_ORIGIN"
  async></script>

Snippet thật do BE trả về khi tạo/sửa site (field snippet).

data-host = origin backend (nơi có /api + widget.html). Cho phép serve widget.js từ CDN/origin khác. Phải là ORIGIN THUẦN (https://host[:port], hoặc http://localhost|127.0.0.1[:port]) — sai định dạng thì widget KHÔNG nạp và in console.error. Thiếu data-host → dùng origin của chính widget.js (hành vi cũ).

Identity verification (đăng nhập sẵn ở trang khách)

Khi website khách đã biết người dùng là ai, gắn thêm data-user-id + data-user-hash để hội thoại được gắn danh tính và liền mạch xuyên thiết bị. data-user-hash = hex(HMAC-SHA256(identity_secret, identifier)).

<script
  src="BACKEND_ORIGIN/widget.js"
  data-site-key="SITE_KEY_HERE"
  data-host="BACKEND_ORIGIN"
  data-user-id="user-42@example.com"
  data-user-hash="<64 hex do SERVER của bạn ký>"
  data-user-name="Nguyễn Văn A"
  data-user-phone="0900000000"
  data-user-email="user-42@example.com"
  async></script>

⚠ KHÔNG BAO GIỜ đặt identity_secret trong HTML/JS trang khách ở production. Secret chỉ nằm ở SERVER của bạn; server ký ra hash rồi render hash vào trang. Widget không đọc secret từ DOM ở bất kỳ đâu.

Reload trang mà không gọi lại setUser/không có data-user-* ⇒ phiên ẩn danh mới (identity KHÔNG được lưu vào localStorage — hash là thông tin phiên của partner, không lưu trên máy dùng chung).

Vector test tay (CHỈ DÙNG Ở DEV)

Sinh hash mẫu bằng shell (secret dưới đây là secret DEV dùng-một-lần, KHÔNG phải secret thật của site production):

# identity_secret DEV mẫu: dev-secret-doi-di-truoc-khi-dung-that
printf '%s' 'user-42@example.com' | openssl dgst -sha256 -hmac 'dev-secret-doi-di-truoc-khi-dung-that' -hex

Đặt đúng secret đó vào panel Identity của site (config omni-channel), rồi thử ở Console:

// gắn danh tính khi người dùng vừa đăng nhập (hash do SERVER ký, ở đây dán tay để test)
cluvixChat.setUser({
  identifier: 'user-42@example.com',
  identifier_hash: '<dán hash 64 hex vừa sinh>',
  name: 'Nguyễn Văn A',
  phone: '0900000000',
});
// hash SAI → BE trả 403, widget hiện text offline, KHÔNG lộ lý do
cluvixChat.setUser({ identifier: 'user-42@example.com', identifier_hash: '0'.repeat(64) });

Public JS API + event

cluvixChat.open();      // mở khung chat
cluvixChat.close();     // đóng
cluvixChat.toggle();    // đảo trạng thái
// gọi TRƯỚC khi widget mount xong vẫn hợp lệ — lệnh được xếp hàng, chạy sau sự kiện ready

cluvixChat.on('ready',   () => console.log('widget sẵn sàng'));
cluvixChat.on('opened',  () => console.log('đã mở'));
cluvixChat.on('closed',  () => console.log('đã đóng'));
// event 'message' CHỈ mang metadata {conversation_id, sent_at} — KHÔNG có nội dung tin nhắn
cluvixChat.on('message', (e) => console.log('có tin nhân viên', e.detail));

// tương đương: window.addEventListener('cluvix-chat:opened', fn)

setUser bị throttle 1 lần/2s và no-op khi CẢ identifier VÀ identifier_hash đều trùng cái đang áp thành công (chống re-handshake storm). Sau lỗi xác thực (hash sai/hết hạn), gọi lại setUser luôn kích handshake mới — kể cả cùng identifier.
